# บันทึกความคืบหน้าแต่ละเฟส

อ่านไฟล์นี้เพื่อดูว่าแต่ละเฟสทำอะไร ทดสอบอย่างไร และเหลืออะไรให้คุณทำเอง

## สิ่งที่รอคุณทำเอง

ระบบยังทำงานต่อได้โดยไม่มีรายการเหล่านี้ แต่ต้องทำก่อนขึ้นเว็บจริง

| รายการ | ต้องทำอะไร | ถ้ายังไม่ทำ |
|---|---|---|
| Resend | สมัคร แล้วใส่ `RESEND_API_KEY`, `EMAIL_FROM` ใน `.env` | ตอนพัฒนา ลิงก์ยืนยันและรีเซ็ตรหัสจะแสดงใน Terminal แทน |
| ที่เก็บรูป | สมัครบริการแบบ S3 เช่น Cloudflare R2 แล้วใส่ `STORAGE_*` ใน `.env` | ตอนพัฒนารูปเก็บใน `public/uploads` แต่บน Vercel จะอัปโหลดไม่ได้ |
| ข้อมูลอะไหล่จริง | แก้ CSV ใน `src/db/seed/csv` หรือกรอกในหลังบ้าน แล้วเปลี่ยน verified เป็น "ตรวจแล้ว" | ระบบใช้ข้อมูลสมมติ 3 แถวต่อหมวด |
| Google OAuth | สร้าง Client ID/Secret ตั้ง Redirect เป็น `http://localhost:3100/api/auth/callback/google` | ปุ่ม Google ถูกซ่อน |

## เฟส 3: ระบบสมาชิก

**ทำแล้ว**

- สมัคร ล็อกอิน ออกจากระบบ ลืมรหัสผ่าน (ลิงก์หมดอายุ 1 ชั่วโมง) ยืนยันอีเมล
- ตั้งค่าบัญชี: ชื่อที่แสดง คำแนะนำตัว เปลี่ยนรหัสผ่าน ออกทุกอุปกรณ์ ลบบัญชี
- ล็อกอินด้วย Google โค้ดพร้อมแล้ว แต่ยังไม่ได้ทดสอบจริงเพราะยังไม่มี Client ID
- จำกัดล็อกอินผิด 5 ครั้งต่อ 15 นาที ต่อ IP และต่อบัญชี
- ตรวจสิทธิ์ 2 ชั้น: `src/proxy.ts` เป็นด่านหน้า และ `src/lib/session.ts` ที่หน้าเว็บกับ Server Action เรียกซ้ำ
- `pnpm admin:promote อีเมล` ตั้งแอดมินคนแรก

**มติ:** เพิ่มตาราง `rate_limits` เป็นตารางที่ 30 และย้ายอัปโหลดรูปโปรไฟล์ไปเฟส 4 พร้อมที่เก็บรูป

**ทดสอบแล้ว** กับเซิร์ฟเวอร์และ PostgreSQL 18 จริง ผ่านทุกข้อ

- สมัครด้วยค่าผิดถูกปฏิเสธฝั่งเซิร์ฟเวอร์ และส่ง `role=admin` มาเองไม่ได้
- คุกกี้เป็น HttpOnly, SameSite=Lax อายุ 7 วัน และเป็น Secure เมื่อรันแบบ Production บน https
- ล็อกหลังผิด 5 ครั้งทั้งเมื่อเปลี่ยน IP และเมื่อเปลี่ยนบัญชี, ระหว่างล็อกรหัสถูกก็เข้าไม่ได้
- Guest และสมาชิกเข้า `/admin` ไม่ได้, ลิงก์รีเซ็ตใช้ซ้ำไม่ได้, คำขอจากเว็บอื่นถูกปฏิเสธ (CSRF)
- ลบบัญชีแล้ว Session และสเปกหายตาม

**ยังไม่ได้ทดสอบ:** ส่งอีเมลจริงผ่าน Resend, ล็อกอิน Google จริง, การทำงานบน Vercel

**ทดสอบเอง**

```bash
pnpm dev
```

เปิด <http://localhost:3100/register> สมัครสมาชิก แล้วดูลิงก์ยืนยันในหน้าจอ Terminal

**อธิบายสำหรับตอบกรรมการ**

- **เก็บรหัสผ่านอย่างไร:** Better Auth แฮชก่อนเก็บ ในฐานข้อมูลไม่มีรหัสแบบอ่านได้ ถ้าข้อมูลรั่วก็ย้อนกลับเป็นรหัสไม่ได้โดยตรง
- **ทำไมตรวจสิทธิ์ 2 ชั้น:** Proxy กันคนเปิดหน้าโดยไม่มีสิทธิ์ แต่ Server Action เรียกตรงได้โดยไม่ผ่านหน้าเว็บ จึงต้องตรวจซ้ำทุกตัว
- **ทำไมตัวนับล็อกอินอยู่ในฐานข้อมูล:** บน Vercel แต่ละคำขออาจอยู่คนละเครื่อง ตัวนับในหน่วยความจำจะนับไม่ตรง และเก็บคีย์แบบแฮชจึงไม่มีอีเมลหรือ IP อ่านได้
- **ทำไมตอบเหมือนกันตอนลืมรหัส:** ไม่ให้คนภายนอกใช้ฟอร์มนี้เช็กว่าอีเมลไหนเป็นสมาชิก

## เฟส 4: หลังบ้านจัดการอะไหล่และนำเข้า CSV

**ทำแล้ว**

- `/admin/parts` ตาราง ค้นหา กรองหมวด แบ่งหน้า แก้ราคาด่วน ซ่อน ลบ
- `/admin/parts/new` และ `/admin/parts/[id]` ฟอร์มกลางบวกสเปกที่เปลี่ยนตามหมวด อัปโหลดรูป ประวัติราคา
- `/admin/parts/import` อัปโหลด CSV พรีวิว แจ้งแถวที่ผิด ยืนยันนำเข้า พร้อมไฟล์ตัวอย่างแต่ละหมวด
- บันทึกประวัติราคาและ `admin_logs` ทุกครั้งที่เพิ่ม แก้ ซ่อน ลบ หรือนำเข้า
- อัปโหลดรูปโปรไฟล์ในหน้าตั้งค่าบัญชี (เลื่อนมาจากเฟส 3)
- CSV ตัวอย่างหมวดละ 3 แถวใน `src/db/seed/csv` **ทุกค่าเป็นข้อมูลสมมติและมีสถานะ "รอตรวจสอบ"** นำเข้าด้วย `pnpm db:seed:samples`

**การตัดสินใจระหว่างที่คุณไม่อยู่**

- ที่เก็บรูปเขียนแบบ S3 จึงเปลี่ยนเป็น R2, Neon หรือ Supabase ได้ด้วยค่าใน `.env` ยังไม่ต้องเลือกตอนนี้
- นำเข้า CSV แบบทั้งหมดหรือไม่เลย ถ้ามีแถวผิดแม้แถวเดียวจะนำเข้าไม่ได้
- ยี่ห้อต้องมีในระบบก่อนนำเข้า ระบบไม่สร้างยี่ห้อใหม่ให้เอง เพื่อกันชื่อยี่ห้อพิมพ์ผิดกลายเป็นยี่ห้อใหม่

**บั๊กที่การทดสอบเจอและแก้แล้ว:** ถ้ากดส่งฟอร์มก่อน JavaScript โหลดเสร็จ ค่าจะไปอยู่ใน URL ซึ่งรวมรหัสผ่านในฟอร์มล็อกอินด้วย จึงตั้งทุกฟอร์มเป็น POST

**ทดสอบแล้ว** บนเว็บจริง: เพิ่มอะไหล่พร้อมข้อความผิดภาษาไทย, ซิงก์ลมไม่มีความสูงถูกปฏิเสธ, ไฟล์ปลอมนามสกุล .png และไฟล์เกิน 2 MB ถูกปฏิเสธ, แก้ราคาแล้วมีประวัติและ Log, ซ่อนอะไหล่, CSV หัวคอลัมน์ผิด ยี่ห้อไม่มี และแถวซ้ำถูกแจ้ง

**ยังไม่ได้ทดสอบ:** อัปโหลดขึ้นบริการ S3 จริง, ปุ่มเปลี่ยนรูปโปรไฟล์บนหน้าเว็บ

**ทดสอบเอง**

```bash
pnpm admin:promote อีเมลของคุณ
```

สมัครบัญชีก่อน แล้วรันคำสั่งนี้เพื่อตั้งเป็นแอดมิน จากนั้นเปิด <http://localhost:3100/admin/parts>

**อธิบายสำหรับตอบกรรมการ**

- **ทำไมฟอร์มเปลี่ยนตามหมวดได้:** `spec-fields.ts` อธิบายช่องของแต่ละหมวดไว้ที่เดียว ทั้งฟอร์มและหัวคอลัมน์ CSV สร้างจากรายการนี้
- **กฎตรวจค่าชุดเดียว:** `partInputSchema` ใช้ทั้งฟอร์ม Server Action และ CSV จึงไม่มีช่องทางใดที่ตรวจหย่อนกว่า
- **ตรวจชนิดไฟล์อย่างไร:** อ่านลายเซ็นต้นไฟล์จริง ไม่เชื่อนามสกุล และตั้งชื่อไฟล์ใหม่แบบสุ่ม
- **Transaction คืออะไร:** ชุดคำสั่งที่สำเร็จพร้อมกันหรือไม่สำเร็จเลย เช่นแก้ราคา เขียนประวัติ และเขียน Log ถ้าอันใดล้มเหลวจะย้อนกลับหมด

## เฟส 5: คลังอะไหล่ ค้นหา ตัวกรอง หน้ารายละเอียด

**ทำแล้ว**

- `/parts` รวมหมวดและค้นหาทุกหมวด, `/parts/[หมวด]` ตัวกรองยี่ห้อ ช่วงราคา สเปกเฉพาะหมวด เรียงลำดับ แบ่งหน้า สลับการ์ด/ตาราง
- ค้นหาแบบพิมพ์แล้วผลขึ้นทันที ด้วย TanStack Query และเก็บตัวกรองใน URL จึงแชร์ลิงก์ได้
- `/parts/[หมวด]/[slug]` รูป สเปกเต็ม ราคาอ้างอิง กราฟประวัติราคา จำนวนสเปกที่ใช้ และสเปกยอดนิยมที่ใช้ชิ้นนี้
- ปุ่มเพิ่มลงสเปกบนทุกการ์ด เก็บใน Zustand และ localStorage
- แถบเมนูบน แถบล่างบนมือถือ ปุ่มลอย "สเปกของฉัน" และ Footer ตามหัวข้อ 5.3

**ทดสอบแล้ว** API 22 ข้อกับฐานข้อมูลจริง: แยกหมวด กรองสเปก กรองราคา เรียงลำดับ ค้นคำไทยและอังกฤษ ค้นจากยี่ห้อ และ SQL Injection ในตัวกรองกับคำค้นไม่มีผล

**ข้อจำกัดที่รู้:** ลิงก์ในเมนูบางอัน (`/builder` `/builds` `/used` `/compare` `/guide` `/about` `/privacy`) ยังเป็น 404 จนกว่าจะถึงเฟสของหน้านั้น และหน้า 404 ของรุ่นที่ไม่มีอยู่แสดงข้อความถูกต้อง แต่รหัส HTTP เป็น 200 เพราะ Next.js ส่งหน้าแบบ Streaming

**อธิบายสำหรับตอบกรรมการ**

- **ทำไมเก็บตัวกรองใน URL:** กดย้อนกลับได้ แชร์ลิงก์ผลการกรองได้ และรีเฟรชแล้วค่าไม่หาย
- **ป้องกัน SQL Injection อย่างไร:** Drizzle ส่งค่าเป็นพารามิเตอร์แยกจากคำสั่ง SQL และชื่อคอลัมน์ที่กรองได้ต้องอยู่ในรายการ `SPEC_FILTERS` เท่านั้น
- **ค้นหาภาษาไทยอย่างไร:** PostgreSQL ไม่มีตัวตัดคำไทย จึงใช้ `search_vector` กับชื่อรุ่นภาษาอังกฤษ และเสริมด้วย ILIKE ให้หาคำกลางชื่อรุ่นเจอ
- **แคชทำงานอย่างไร:** หน้าโหลดเร็วเพราะเก็บผลไว้ และเมื่อแอดมินแก้อะไหล่ `updateTag('parts')` จะล้างแคชทันที

## เฟส 6: Compatibility Engine

**ทำแล้ว**

- `src/lib/compat` ฟังก์ชันล้วน ไม่แตะฐานข้อมูล ใช้ได้ทั้งเบราว์เซอร์และเซิร์ฟเวอร์
- กฎ R01–R18 ครบ และข้อความระดับข้อมูล I01–I04 (หมวดไม่ครบ, ไม่มีชุดระบายความร้อน, เกินงบ, แรมแถวเดียว)
- สูตรกำลังไฟและ PSU แนะนำ ใช้ค่าเผื่อ 30% ชุดเดียวกับเกจและ R14 ตามมติ Q2
- คะแนนถ่วงน้ำหนักตามการใช้งาน ความคุ้มค่า และราคารวมแบบผสมมือสอง
- `checkBuild()` จุดเข้าเดียว และ `evaluateCandidate()` สำหรับตัวกรองอัจฉริยะในเฟส 7
- ตั้งค่า Vitest พร้อมเกณฑ์ความครอบคลุม 90%

**ทดสอบแล้ว** 78 เทสต์ผ่านทั้งหมด ทุกกฎมีกรณีผ่านและไม่ผ่าน ความครอบคลุมบรรทัด 100% และตรวจสเปกเต็มชุดได้เร็วกว่า 100 ms ตามหัวข้อ 9.2 มาก

**ทดสอบเอง**

```bash
pnpm test:coverage
```

รายงาน HTML อยู่ที่ `coverage/index.html`

**ข้อจำกัดที่รู้:** ยังไม่มีหน้าเว็บเรียกใช้ จะเห็นผลจริงในหน้าจัดสเปกเฟส 7 และค่าตั้งค่า (ค่าเผื่อ วัตต์บอร์ด น้ำหนักคะแนน) ยังใช้ค่าตั้งต้นในโค้ด จะอ่านจากตาราง `settings` เมื่อทำหน้าตั้งค่าระบบในเฟส 12

**อธิบายสำหรับตอบกรรมการ** ดูฉบับเต็มที่ [compat-engine.md](compat-engine.md) ครอบคลุมทุกกฎ เหตุผลของระดับ สูตรวัตต์พร้อมตัวอย่าง คะแนน และตัวกรองอัจฉริยะ

## เฟส 7: หน้าจัดสเปก เกจกำลังไฟ ตัวกรองอัจฉริยะ บันทึก แชร์ QR

**ทำแล้ว**

- `/builder` 8 ช่องอะไหล่ เลือกแรมและเก็บข้อมูลได้หลายชิ้นพร้อมจำนวน ตั้งชื่อ คำอธิบาย งบ และประเภทการใช้งาน
- ผลตรวจ ราคา วัตต์ และคะแนนเปลี่ยนทันทีทุกครั้งที่แก้ เพราะ Engine ทำงานในเบราว์เซอร์
- แผงสรุปด้านข้าง: สถานะรวม ราคา แถบใช้งบ เกจกำลังไฟครึ่งวงกลม จำนวนปัญหาแต่ละระดับ คะแนนและความคุ้มค่า บนมือถือเป็นแถบด้านล่างที่กดเปิดแผงเต็มได้
- ช่องที่มีปัญหามีกรอบสีและป้ายรหัสกฎ กดไปดูวิธีแก้ได้
- หน้าต่างเลือกอะไหล่: ค้นหา ตัวกรองยี่ห้อ ราคา สเปกเฉพาะหมวด เรียงลำดับ แบ่งหน้า สวิตช์กรองอัจฉริยะ และป้ายเข้ากันได้/ไม่ได้ทุกชิ้น
- ปุ่มแนะนำอะไหล่ทดแทนใต้ปัญหา เปิดหมวดที่ต้องเปลี่ยนพร้อมตัวกรอง เรียงจากราคาใกล้ชิ้นเดิม และแสดงเฉพาะชิ้นที่แก้ปัญหานั้นได้
- ย้อนกลับ/ทำซ้ำ (ปุ่ม และ Ctrl+Z / Ctrl+Shift+Z)
- บันทึกอัตโนมัติหลังหยุดแก้ 2 วินาทีเมื่อล็อกอิน ผู้เยี่ยมชมเก็บไว้ในเครื่อง ล็อกอินแล้วสเปกย้ายเข้าบัญชีเอง
- `saveBuild` บนเซิร์ฟเวอร์ตรวจสิทธิ์ ตรวจค่าด้วย Zod อ่านราคาและสเปกจากฐานข้อมูลเอง รัน Engine ซ้ำ แล้วบันทึกใน Transaction
- แชร์: ลิงก์สั้น `/b/รหัส` QR Code เลือกใครเห็นได้ (สเปกส่วนตัวเปลี่ยนเป็น "ทุกคนที่มีลิงก์" ตอนกดแชร์)
- `/builds/[id]` หน้ารายละเอียดสเปก (โหวต คอมเมนต์ Fork ในเฟส 10) และ `/api/og/build/[id]` รูปสรุป 1200 × 630 ใช้เป็นพรีวิวลิงก์และดาวน์โหลดได้

**ทดสอบแล้ว**

- 89 เทสต์ผ่าน เพิ่มเทสต์ตัวกรองอัจฉริยะ โหมดแก้ปัญหา ตัวกรอง การเรียง แบ่งหน้า ตัวตรวจค่า รหัสสเปก และสิทธิ์ดูสเปก

- บน production build ในเครื่องด้วยบัญชีทดสอบ (ข้อมูลทดสอบลบออกแล้ว): โหวตขึ้นได้ 1 → สลับเป็นโหวตลงได้ −1 และฐานข้อมูลตรงกัน, รายการโปรดนับ 1, คอมเมนต์ที่มี `<b>` แสดงเป็นตัวอักษรไม่ใช่ HTML, ตอบกลับได้และคำตอบไม่มีปุ่มตอบซ้อน, Fork ได้สเปกส่วนตัวใหม่พร้อม `forked_from_id` แล้วเปิดหน้าจัดสเปกต่อ, เจ้าของได้แจ้งเตือนโหวต คอมเมนต์ และ Fork, รายงานสเปกได้และรายงานซ้ำถูกปฏิเสธ, หน้าเทียบแสดงหมวดที่ต่างกันและสรุป ถูกกว่า / ประหยัดไฟกว่า / สูงกว่า
- ผู้เยี่ยมชม: สเปกส่วนตัวของคนอื่นไม่โผล่ในหน้าเทียบ, โปรไฟล์ไม่มีอีเมล, `/me/builds` ถูกส่งไปหน้าเข้าสู่ระบบ

**ยังไม่มี:** แจ้งเตือนแบบสดและหน้า `/me/notifications` (เฟส 11) หน้าจัดการรายงานของแอดมิน (เฟส 12) จำนวนผู้เข้าชม `view_count` ยังไม่นับ

**ทดสอบเอง** เปลี่ยนสเปกหนึ่งชุดเป็น "สาธารณะ" ที่หน้าสเปกของฉัน แล้วเปิดด้วยอีกบัญชีเพื่อโหวต คอมเมนต์ และ Fork

**อธิบายสำหรับตอบกรรมการ**

- **โหวตซ้ำได้ไหม:** ไม่ได้ ตาราง `build_votes` ใช้ (build_id, user_id) เป็น Primary Key โหวตใหม่จึงเป็นการแก้ค่าเดิม และ `vote_score` คำนวณใหม่จากผลรวมในตารางทุกครั้ง ไม่ใช่บวกลบทีละหนึ่ง จึงไม่เพี้ยนแม้หลายคนกดพร้อมกัน
- **ยอดนิยมสัปดาห์คิดยังไง:** รวมเฉพาะโหวตที่เกิดใน 7 วันล่าสุด สเปกเก่าที่คะแนนสะสมสูงจึงไม่ครองอันดับตลอด
- **กันคอมเมนต์อันตราย:** เก็บเป็นตัวอักษรล้วน React escape ตอนแสดง ไม่แปลงเป็น HTML จำกัด 1,000 ตัวอักษรและ 10 ครั้งต่อนาที ต้องยืนยันอีเมลก่อน
- **Fork ต่างจากคัดลอกยังไง:** Fork สเปกของคนอื่นเก็บ `forked_from_id` และแจ้งเจ้าของ คัดลอกสเปกตัวเองไม่ถือเป็น Fork ทั้งสองแบบคำนวณราคาและผลตรวจใหม่จากข้อมูลอะไหล่ล่าสุด

## เฟส 11: แจ้งเตือนแบบสด

**ทำแล้ว**

- `/api/notifications/stream` Server-Sent Events: ส่งจำนวนที่ยังไม่อ่านและรายการล่าสุดตอนเชื่อมต่อ แล้ววนอ่านแถวใหม่ทุก 3 วินาที ping ทุก 15 วินาที ปิดเองที่ 50 วินาที (ขีดจำกัดเวลาของ Vercel) เบราว์เซอร์ต่อใหม่เองใน 2 วินาที พร้อม `Last-Event-ID` จึงไม่พลาดรายการ
- กระดิ่งแจ้งเตือนบนแถบเมนู: ป้ายจำนวนที่ยังไม่อ่าน รายการล่าสุด 8 รายการ อ่านทั้งหมด กดแล้วไปหน้าที่เกี่ยวข้อง และกล่องแจ้งเตือนเด้งมุมจอ (`role="status"` โปรแกรมอ่านหน้าจออ่านให้)
- `/me/notifications` ทั้งหมด / ยังไม่อ่าน ทำเครื่องหมายว่าอ่าน และดูเก่ากว่านี้
- ตั้งค่าเปิด/ปิดการแจ้งเตือน 7 ประเภทใน `/me/settings` (ประกาศจากระบบปิดไม่ได้) เก็บในคอลัมน์ใหม่ `users.muted_notifications` (migration 0004)
- แจ้งเตือนราคาเปลี่ยน: แอดมินแก้ราคาในหน้าจัดการอะไหล่ ฟอร์มแก้อะไหล่ หรือนำเข้า CSV → เจ้าของสเปกที่มีชิ้นนั้นได้แจ้งเตือน "ลดลง/เพิ่มขึ้น ฿X เป็น ฿Y" เทียบกับราคาตอนเพิ่มลงสเปก
- ทุกการแจ้งเตือน (ชุมชน มือสอง ราคา) ผ่าน `notify()` ใน `src/server/notify.ts` จุดเดียว: ไม่แจ้งตัวเอง และข้ามประเภทที่ผู้รับปิดไว้

**ทดสอบแล้ว**

- 159 เทสต์ผ่าน เพิ่ม 4 เทสต์ (เวลาแบบสั้น ลิงก์ปลายทาง ประเภทที่ปิดได้)
- บน production build ในเครื่อง (ข้อมูลทดสอบลบออกแล้ว)
  - เพิ่มการแจ้งเตือนในฐานข้อมูลขณะเปิดหน้าทิ้งไว้ ป้ายบนกระดิ่งและกล่องเด้งขึ้นภายใน 3 วินาที
  - กด "อ่านทั้งหมด" ฐานข้อมูลบันทึก `read_at`
  - EventSource ปิดที่ 51 วินาที ต่อใหม่ที่ 53 วินาทีพร้อม Last-Event-ID แล้วรับรายการถัดไปได้ (ทดสอบ 2 รอบ)
  - แอดมินลดราคา CPU ที่อยู่ในสเปกของอีกบัญชี เจ้าของสเปกได้แจ้งเตือน "ลดลง ฿300 เป็น ฿5,600" แอดมินที่เป็นเจ้าของสเปกอื่นที่มีชิ้นนี้ไม่ได้แจ้งเตือนตัวเอง
  - ปิดประเภท "ราคาเปลี่ยน" แล้วเปลี่ยนราคาอีกครั้ง ไม่มีแจ้งเตือนใหม่

**ปัญหาที่เจอ:** ตอนทดสอบสตรีมครั้งแรกผมเข้าใจผิดว่าตัวจับเวลาบนเซิร์ฟเวอร์ไม่ทำงาน สาเหตุจริงคือสคริปต์ทดสอบเรียก `reader.read()` ซ้อนกันจนข้อมูลไปตกที่คำสั่งที่ทิ้งไปแล้ว ระหว่างนั้นได้เปลี่ยนเป็นลูปเดียวที่หยุดด้วย `cancel()` ของสตรีม ซึ่งเข้าใจง่ายกว่าเดิม

**ทดสอบเอง** เปิดเว็บสองเบราว์เซอร์ด้วยสองบัญชี ให้บัญชีหนึ่งคอมเมนต์สเปกสาธารณะของอีกบัญชี กระดิ่งของเจ้าของจะขึ้นเองภายในไม่กี่วินาที

**อธิบายสำหรับตอบกรรมการ**

- **ทำไมใช้ SSE ไม่ใช้ WebSocket:** แจ้งเตือนส่งทางเดียวจากเซิร์ฟเวอร์ไปเบราว์เซอร์ SSE ใช้ HTTP ธรรมดา เบราว์เซอร์ต่อใหม่ให้เอง และทำใน Next.js ได้โดยไม่ต้องมีเซิร์ฟเวอร์แยก (หัวข้อ 7)
- **ทำไมต้องวนอ่านฐานข้อมูล:** บน Vercel คนคอมเมนต์กับเจ้าของสเปกอาจต่อเข้าคนละเครื่อง ส่งผ่านหน่วยความจำไม่ได้ ตาราง `notifications` จึงเป็นตัวกลาง และ Index `(user_id, read_at)` ทำให้นับที่ยังไม่อ่านได้เร็ว
- **ไม่พลาดรายการตอนต่อใหม่ได้อย่างไร:** ทุก event มี `id` เป็นรหัสแถว เบราว์เซอร์ส่ง `Last-Event-ID` กลับมาตอนต่อใหม่ เซิร์ฟเวอร์ส่งเฉพาะแถวที่รหัสมากกว่านั้น
