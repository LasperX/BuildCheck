
# เอกสารโปรเจค: เว็บจัดสเปกคอมพร้อมเช็กความเข้ากันได้

Nov 5, 2026 · @Worawit

## 1. ภาพรวมโปรเจค

โปรเจคนี้คือเว็บไซต์ที่ให้ผู้ใช้เลือกอะไหล่คอมพิวเตอร์มาประกอบเป็นชุด แล้วระบบตรวจทันทีว่าใส่ด้วยกันได้หรือไม่ ไฟพอหรือไม่ และราคารวมเท่าไหร่ ข้อมูลอะไหล่ทั้งหมดแอดมินกรอกเอง ไม่ดึงจากแหล่งภายนอก และไม่มีการขายสินค้าจริง

### 1.1 ชื่อโปรเจค

- ภาษาไทย: เว็บไซต์จัดสเปกคอมพิวเตอร์พร้อมระบบตรวจสอบความเข้ากันได้ของอุปกรณ์
- ภาษาอังกฤษ: BuildCheck – PC Spec Builder with Compatibility Checking System
- ชื่อเว็บ (เปลี่ยนได้): BuildCheck

### 1.2 ที่มาและความสำคัญ

คนที่อยากประกอบคอมเองมักไม่รู้ว่าอะไหล่ตัวไหนใส่กันได้ เช่น ซื้อ CPU กับเมนบอร์ดคนละ Socket ซื้อแรม DDR5 มาใส่บอร์ด DDR4 หรือการ์ดจอยาวเกินเคส ความผิดพลาดเหล่านี้ทำให้เสียเงินและเวลา
เว็บจัดสเปกที่มีอยู่ส่วนใหญ่เป็นภาษาอังกฤษ หรือเป็นของร้านค้าที่ผูกกับการขายสินค้า ผู้เริ่มต้นชาวไทยจึงขาดเครื่องมือกลางที่อธิบายเป็นภาษาไทยว่าทำไมถึงใส่ไม่ได้ และควรเปลี่ยนเป็นอะไร

### 1.3 ปัญหาที่ต้องการแก้

- ผู้ใช้ไม่รู้ว่าอะไหล่ใดเข้ากันได้
- ผู้ใช้คำนวณกำลังไฟไม่เป็น จึงเลือก PSU ผิดขนาด
- ผู้ใช้มีงบจำกัด แต่ไม่รู้ว่าควรแบ่งงบไปที่อะไหล่ส่วนไหน
- ไม่มีพื้นที่ให้แชร์สเปกและขอความเห็นจากคนอื่นอย่างเป็นระบบ

### 1.4 วัตถุประสงค์

- เพื่อพัฒนาเว็บไซต์จัดสเปกคอมพิวเตอร์ที่ตรวจสอบความเข้ากันได้ของอะไหล่แบบอัตโนมัติและเรียลไทม์
- เพื่อพัฒนาระบบคำนวณกำลังไฟฟ้ารวมและแนะนำขนาด PSU ที่เหมาะสม
- เพื่อพัฒนาระบบจัดสเปกตามงบประมาณและประเภทการใช้งาน
- เพื่อพัฒนาชุมชนแชร์ โหวต และแสดงความคิดเห็นต่อสเปก
- เพื่อพัฒนาระบบหลังบ้านให้แอดมินจัดการข้อมูลอะไหล่และดูสถิติการใช้งาน
- เพื่อประเมินความพึงพอใจของผู้ใช้ที่มีต่อเว็บไซต์

### 1.5 ขอบเขตของโปรเจค

สิ่งที่ทำ
- อะไหล่ 8 หมวด: CPU, เมนบอร์ด, แรม, การ์ดจอ, อุปกรณ์เก็บข้อมูล, PSU, เคส, ชุดระบายความร้อน
- จัดสเปกได้ทั้งของมือหนึ่ง มือสอง หรือผสมกัน พร้อมราคาตลาดมือสองอ้างอิง
- ผู้ใช้ 3 ระดับ: ผู้เยี่ยมชม สมาชิก แอดมิน
- ตรวจความเข้ากันได้ 18 กฎ และกฎเฉพาะของมือสองอีก 6 กฎ
- รองรับคอมพิวเตอร์ แท็บเล็ต และมือถือ
- รองรับภาษาไทยเป็นหลัก และโหมดสว่าง/มืด
- ข้อมูลอะไหล่ตั้งต้นประมาณ 150–200 รายการ ที่แอดมินกรอกเอง
สิ่งที่ไม่ทำ
- ไม่ขายสินค้า ไม่มีระบบชำระเงิน ไม่มีตะกร้าสินค้า ไม่เป็นตลาดซื้อขายมือสอง
- ไม่ดึงราคาหรือข้อมูลจากเว็บไซต์ร้านค้า กลุ่ม Facebook หรือแอปซื้อขายอัตโนมัติ ราคามือสองมาจากแอดมินสำรวจและสมาชิกรายงานเท่านั้น
- ไม่ใช้ AI ในการแนะนำ ใช้สูตรและเงื่อนไขที่เขียนเองทั้งหมด
- ไม่รวมอุปกรณ์ต่อพ่วง เช่น จอ คีย์บอร์ด เมาส์

### 1.6 ประโยชน์ที่คาดว่าจะได้รับ

- ผู้ใช้ประกอบคอมได้ถูกต้อง ลดการซื้ออะไหล่ผิด
- ผู้เริ่มต้นเข้าใจเหตุผลของแต่ละข้อจำกัดผ่านคำอธิบายภาษาไทย
- ผู้ใช้วางแผนงบได้ชัดเจนก่อนไปซื้อจริง
- ผู้พัฒนาได้ฝึกการออกแบบฐานข้อมูลเชิงสัมพันธ์ การเขียนตรรกะเงื่อนไขซับซ้อน และเว็บแบบ Full-stack สมัยใหม่

## 2. กลุ่มผู้ใช้และสิทธิ์

ระบบมีผู้ใช้ 3 ระดับ แต่ละระดับเห็นและทำได้ไม่เท่ากัน สิทธิ์ตรวจทั้งฝั่งหน้าเว็บและฝั่งเซิร์ฟเวอร์

### 2.1 ผู้เยี่ยมชม (Guest)

คนที่ยังไม่ได้ล็อกอิน ทดลองจัดสเปกได้เต็มที่ แต่สเปกเก็บไว้ในเบราว์เซอร์ชั่วคราว ถ้าสมัครสมาชิกภายหลัง ระบบย้ายสเปกที่จัดค้างไว้เข้าบัญชีให้อัตโนมัติ

### 2.2 สมาชิก (Member)

คนที่สมัครและล็อกอินแล้ว บันทึกสเปกได้ไม่จำกัด แชร์ โหวต คอมเมนต์ ติดตามสเปกของคนอื่น และรับการแจ้งเตือน

### 2.3 แอดมิน (Admin)

ผู้ดูแลระบบ จัดการข้อมูลอะไหล่ทั้งหมด จัดการผู้ใช้ ตรวจรายงานเนื้อหาไม่เหมาะสม และดู Dashboard สถิติ

## 3. ฟีเจอร์ทั้งหมด

ระบบแบ่งเป็น 10 โมดูล โมดูลที่ 3–5 คือหัวใจของโปรเจค ส่วนที่เหลือทำให้เว็บครบเป็นระบบจริง

### 3.1 โมดูลสมาชิก (Authentication)

- สมัครสมาชิกด้วยอีเมล ชื่อผู้ใช้ และรหัสผ่าน
- ยืนยันอีเมลด้วยลิงก์ก่อนใช้งานฟีเจอร์ชุมชน
- ล็อกอินด้วยอีเมล/รหัสผ่าน หรือบัญชี Google
- ลืมรหัสผ่าน รับลิงก์รีเซ็ตทางอีเมล (หมดอายุใน 1 ชั่วโมง)
- แก้ไขโปรไฟล์: รูป ชื่อที่แสดง คำแนะนำตัว
- เปลี่ยนรหัสผ่าน และออกจากระบบทุกอุปกรณ์
- ลบบัญชีของตัวเอง

### 3.2 โมดูลคลังอะไหล่ (Parts Catalog)

- แสดงอะไหล่แยกตาม 8 หมวด เป็นการ์ดหรือตาราง สลับได้
- ค้นหาจากชื่อรุ่นหรือยี่ห้อ พิมพ์แล้วผลขึ้นทันที
- กรองตามยี่ห้อ ช่วงราคา และสเปกเฉพาะหมวด เช่น Socket, ความจุ, ขนาดบอร์ด
- เรียงตามราคา ความนิยม หรือรุ่นใหม่ล่าสุด
- หน้ารายละเอียดอะไหล่: รูป สเปกเต็ม ราคาอ้างอิง กราฟประวัติราคาที่แอดมินบันทึก และจำนวนสเปกที่ใช้อะไหล่นี้
- ปุ่มเพิ่มลงสเปกที่กำลังจัดได้จากทุกหน้า

### 3.3 โมดูลจัดสเปก (Builder)

- หน้าจัดสเปกแสดง 8 ช่องตามหมวด กดแต่ละช่องเพื่อเปิดหน้าต่างเลือกอะไหล่
- เลือกอะไหล่บางหมวดได้หลายชิ้น เช่น แรมหลายแถว SSD หลายตัว พร้อมระบุจำนวน
- ราคารวม วัตต์รวม และสถานะความเข้ากันได้อัปเดตทันทีทุกครั้งที่เปลี่ยนอะไหล่
- โหมดกรองอัจฉริยะ: เปิดแล้วหน้าต่างเลือกแสดงเฉพาะอะไหล่ที่เข้ากับของที่เลือกไว้ ปิดแล้วแสดงทั้งหมดแต่ติดป้ายเตือน
- แผงสรุปด้านข้าง: ราคารวม เกจกำลังไฟ จำนวนปัญหาแยกตามระดับ
- ตั้งชื่อสเปก ใส่คำอธิบาย ตั้งงบ และเลือกประเภทการใช้งาน
- บันทึกอัตโนมัติขณะแก้ไข และย้อนกลับ/ทำซ้ำได้
- สร้างลิงก์แชร์สั้นและ QR Code ของสเปก
- ส่งออกสเปกเป็นรูปภาพสรุปสำหรับโพสต์ลงโซเชียล

### 3.4 โมดูลตรวจความเข้ากันได้ (Compatibility Engine)

- ตรวจทุกครั้งที่สเปกเปลี่ยน ใช้โค้ดชุดเดียวกันทั้งฝั่งหน้าเว็บและเซิร์ฟเวอร์
- ผลแบ่ง 3 ระดับ: ผิดพลาด (ใส่ไม่ได้) เตือน (ใส่ได้แต่มีความเสี่ยง) ผ่าน
- แต่ละปัญหาบอกอะไหล่ที่เกี่ยวข้อง สาเหตุเป็นภาษาไทย และวิธีแก้
- ปุ่มแนะนำอะไหล่ทดแทนที่แก้ปัญหานั้นได้ เรียงจากราคาใกล้เคียงที่สุด
- รายละเอียดกฎทั้งหมดอยู่ในหัวข้อที่ 4

### 3.5 โมดูลจัดสเปกตามงบ (Budget Builder)

- ผู้ใช้ใส่งบ เลือกประเภทการใช้งาน (เล่นเกม ทำงานออฟฟิศ ตัดต่อ/กราฟิก สตรีม) และยี่ห้อ CPU ที่ชอบ (ไม่บังคับ)
- ระบบแบ่งงบตามสัดส่วนของประเภทการใช้งาน แล้วเลือกชุดอะไหล่ที่เข้ากันได้และคะแนนประสิทธิภาพสูงสุดภายในงบ
- แสดง 3 ตัวเลือก: ประหยัด สมดุล คุ้มสุด
- กดนำไปแก้ต่อในหน้าจัดสเปกได้ทันที

### 3.6 โมดูลเทียบสเปก (Compare)

- เลือก 2–3 สเปกมาเทียบแบบคอลัมน์ข้างกัน
- ไฮไลต์ช่องที่ต่างกัน และบอกว่าสเปกไหนแรงกว่าในแต่ละหมวด
- เทียบราคารวม วัตต์รวม และคะแนนประสิทธิภาพรวม

### 3.7 โมดูลชุมชน (Community)

- หน้ารวมสเปกสาธารณะ กรองตามประเภทการใช้งานและช่วงงบ
- โหวตขึ้น/ลง คอมเมนต์ ตอบกลับคอมเมนต์ได้ 1 ชั้น
- บันทึกสเปกเป็นรายการโปรด
- Fork สเปกของคนอื่นมาแก้เป็นของตัวเอง โดยระบบเก็บว่าต้นฉบับมาจากใคร
- อันดับสเปกยอดนิยมประจำสัปดาห์และตลอดกาล
- หน้าโปรไฟล์สาธารณะของสมาชิก แสดงสเปกที่แชร์และคะแนนโหวตรวม
- รายงานเนื้อหาไม่เหมาะสม

### 3.8 โมดูลแจ้งเตือน (Notifications)

- แจ้งเตือนในเว็บแบบเรียลไทม์เมื่อมีคนคอมเมนต์ โหวต หรือ Fork สเปกของเรา
- แจ้งเตือนเมื่อแอดมินปรับราคาอะไหล่ในสเปกที่เราบันทึกไว้
- ตั้งค่าเปิด/ปิดการแจ้งเตือนแต่ละประเภท

### 3.9 โมดูลหลังบ้าน (Admin Panel)

- จัดการอะไหล่: เพิ่ม แก้ ลบ อัปโหลดรูป กรอกสเปกตามแบบฟอร์มของแต่ละหมวด
- นำเข้าอะไหล่จำนวนมากจากไฟล์ CSV ที่แอดมินเตรียมเอง
- ปรับราคา ระบบเก็บประวัติราคาทุกครั้ง
- จัดการค่าคงที่ของกฎ เช่น เปอร์เซ็นต์เผื่อกำลังไฟ
- จัดการผู้ใช้: ค้นหา ดูกิจกรรม ระงับ/ปลดระงับ
- จัดการรายงาน: ดู ซ่อนเนื้อหา ปิดรายงาน
- บันทึกการทำงานของแอดมิน (ใครแก้อะไร เมื่อไหร่)

### 3.10 โมดูลรายงานสถิติ (Dashboard)

- ตัวเลขสรุป: สมาชิกทั้งหมด สมาชิกใหม่ จำนวนสเปก จำนวนอะไหล่
- กราฟสมาชิกใหม่และสเปกใหม่รายวัน
- อะไหล่ที่ถูกเลือกบ่อยที่สุด 10 อันดับในแต่ละหมวด
- สัดส่วนยี่ห้อ CPU และการ์ดจอในสเปกทั้งหมด
- งบเฉลี่ยแยกตามประเภทการใช้งาน
- ปัญหาความเข้ากันได้ที่เกิดบ่อยที่สุด

### 3.11 โมดูลอะไหล่มือสอง (Used Parts)

- ทุกช่องในหน้าจัดสเปกสลับได้ว่าใช้ มือหนึ่ง หรือ มือสอง และเลือกเกรดสภาพ A (ดีมาก มีประกัน) · B (ใช้งานปกติ มีรอย) · C (มีตำหนิ ไม่มีกล่อง)
- ราคามือสองมาจากราคากลางตลาดของระบบ แสดงราคากลาง ช่วงราคาที่พบบ่อย จำนวนรายงาน วันที่อัปเดต และป้ายความน่าเชื่อถือ (สูง/กลาง/ประมาณการ)
- ช่อง ราคาที่เจอจริง ใส่ราคาที่ผู้ขายเสนอ ระบบบอกทันทีว่า ถูก · สมเหตุสมผล · แพงกว่าตลาด · ถูกผิดปกติ (ระวังของเสียหรือมิจฉาชีพ)
- แผงสรุปแสดงราคารวมแบบผสม และยอดที่ประหยัดได้เมื่อเทียบกับซื้อใหม่ทั้งชุด
- สมาชิกรายงานราคามือสองที่เห็นหรือซื้อจริง: ราคา เกรด ช่องทาง (กลุ่ม Facebook, แอปซื้อขาย, ร้านมือสอง, คนรู้จัก) จังหวัด วันที่ ประกันที่เหลือ และแนบรูปหลักฐานได้
- หน้ารายละเอียดอะไหล่มีแท็บ ราคามือสอง กราฟแนวโน้มราคากลางรายสัปดาห์แยกตามเกรด และรายงานล่าสุด
- หน้า ตลาดมือสอง รวมอะไหล่ที่ราคาลดมากที่สุดในเดือนนี้ และรุ่นที่ถูกรายงานบ่อย
- เช็กลิสต์ก่อนซื้อเฉพาะหมวด เช่น การ์ดจอขอดูรันทดสอบ 15 นาที · SSD ดูค่า Health · CPU ดูขาหรือฐาน Socket ไม่งอ · แรมรันทดสอบหน่วยความจำ
- กฎเตือนเฉพาะมือสอง U01–U06 (หัวข้อ 4.6)
- ตั้งเตือนราคา: แจ้งเมื่อราคากลางมือสองของรุ่นที่สนใจลดถึงราคาที่ตั้งไว้
- จัดสเปกตามงบมีตัวเลือก ยอมใช้มือสอง เลือกได้ว่าหมวดไหนยอมเป็นมือสอง (PSU ปิดไว้เป็นค่าเริ่มต้น)
- แอดมินอนุมัติ/ปฏิเสธรายงานราคา และบันทึกราคากลางจากการสำรวจตลาดเอง

## 4. ตรรกะการตรวจและการคำนวณ

ส่วนนี้คือจุดที่ทำให้โปรเจคยากและน่าสนใจ ระบบมี 18 กฎตรวจความเข้ากันได้ สูตรคำนวณกำลังไฟ คะแนนประสิทธิภาพ และอัลกอริทึมจัดสเปกตามงบ ทั้งหมดเขียนเป็นฟังก์ชัน TypeScript ล้วนในแพ็กเกจเดียว ใช้ร่วมกันทั้งหน้าเว็บและเซิร์ฟเวอร์

### 4.1 กฎตรวจความเข้ากันได้

ระดับ: ผิดพลาด = ประกอบไม่ได้หรือเปิดไม่ติด · เตือน = ใช้ได้แต่เสียประสิทธิภาพหรือเสี่ยง · ข้อมูล = คำแนะนำทั่วไป

| รหัส | ตรวจอะไร | เงื่อนไขที่ถือว่ามีปัญหา | ระดับ |
|---|---|---|---|
| R01 | CPU ↔ เมนบอร์ด | cpu.socket ≠ mb.socket | ผิดพลาด |
| R02 | CPU ↔ ชิปเซ็ต | รุ่น CPU ไม่อยู่ในรายการรุ่นที่ชิปเซ็ตรองรับ | ผิดพลาด |
| R03 | CPU ↔ BIOS | ชิปเซ็ตรองรับ แต่ต้องอัปเดต BIOS ก่อน | เตือน |
| R04 | ชนิดแรม | ram.type ≠ mb.memory_type (DDR4/DDR5) | ผิดพลาด |
| R05 | จำนวนแถวแรม | แถวแรมรวม > mb.memory_slots | ผิดพลาด |
| R06 | ความจุแรม | ความจุรวม > mb.max_memory_gb | ผิดพลาด |
| R07 | ความเร็วแรม | ram.speed > mb.max_memory_speed (จะวิ่งช้าลง) | เตือน |
| R08 | เมนบอร์ด ↔ เคส | mb.form_factor ไม่อยู่ในรายการขนาดบอร์ดที่เคสรองรับ | ผิดพลาด |

| R10 | ซิงก์ลม ↔ เคส | cooler.height_mm > case.max_cooler_height_mm | ผิดพลาด |
| R11 | ชุดน้ำ ↔ เคส | ขนาดหม้อน้ำไม่อยู่ในรายการที่เคสรองรับ | ผิดพลาด |
| R12 | ชุดระบายความร้อน ↔ Socket | Socket ของ CPU ไม่อยู่ในรายการที่ชุดระบายความร้อนรองรับ | ผิดพลาด |
| R13 | ระบายความร้อนพอหรือไม่ | cooler.max_tdp < cpu.tdp | เตือน |
| R14 | กำลังไฟ PSU | วัตต์ PSU ต่ำกว่าวัตต์ที่ใช้จริง → ผิดพลาด · เผื่อไม่ถึง 20% → เตือน | ผิดพลาด / เตือน |
| R15 | PSU ↔ เคส | ขนาด PSU (ATX/SFX) เคสไม่รองรับ | ผิดพลาด |
| R16 | ช่องเสียบไฟการ์ดจอ | สายไฟการ์ดจอที่ PSU มีไม่พอกับที่การ์ดจอต้องการ | เตือน |
| R17 | ช่อง M.2 / SATA | SSD M.2 เกินจำนวนช่อง M.2 หรือไดรฟ์ SATA เกินจำนวนพอร์ต SATA | ผิดพลาด |
| R18 | ไม่มีภาพออกจอ | CPU ไม่มีกราฟิกในตัว และไม่ได้เลือกการ์ดจอ | ผิดพลาด |

ข้อความแนะนำเพิ่มเติมระดับ ข้อมูล: ยังเลือกอะไหล่ไม่ครบหมวดจำเป็น · CPU ไม่มีพัดลมแถมและยังไม่เลือกชุดระบายความร้อน · ราคารวมเกินงบที่ตั้งไว้ · ใส่แรมแถวเดียว (แนะนำ 2 แถวเพื่อ Dual Channel)
ตัวอย่างผลตรวจที่ผู้ใช้เห็น:
❌ R01 Socket ไม่ตรงกัน — Intel Core i5-14400F ใช้ Socket LGA1700 แต่ ASUS TUF B650-PLUS ใช้ AM5 ทั้งสองชิ้นใส่ด้วยกันไม่ได้ · [ดูเมนบอร์ด LGA1700 ในงบใกล้เคียง]

### 4.2 ขั้นตอนการตรวจ

- รับสเปกปัจจุบัน (รายการอะไหล่และจำนวน)
- ดึงข้อมูลสเปกเชิงเทคนิคของอะไหล่ทุกชิ้น
- รันทุกกฎ กฎที่อะไหล่ยังเลือกไม่ครบจะข้าม
- รวมผลเป็นรายการปัญหา เรียงจากผิดพลาด เตือน แล้วข้อมูล
- สรุปสถานะรวม: มีผิดพลาดอย่างน้อย 1 ข้อ = แดง · มีแต่เตือน = เหลือง · ไม่มีเลย = เขียว
- ฝั่งหน้าเว็บแสดงผลทันที ฝั่งเซิร์ฟเวอร์ตรวจซ้ำตอนบันทึก และเก็บสถานะไว้ในตาราง builds

### 4.3 สูตรคำนวณกำลังไฟ

วัตต์ที่ใช้จริงโดยประมาณ:
W_{total} = TDP_{CPU} + TBP_{GPU} + W_{MB} + 5 \cdot n_{RAM} + 7 \cdot n_{SSD} + 10 \cdot n_{HDD} + W_{cooler} + 15
- W_MB = 50 วัตต์ (บอร์ดทั่วไป) หรือ 80 วัตต์ (ชิปเซ็ตระดับสูง) ตามค่าที่แอดมินกรอก
- W_cooler = 5 วัตต์ (ซิงก์ลม) หรือ 15 วัตต์ (ชุดน้ำ)
- 15 วัตต์สุดท้ายคือพัดลมเคสและพอร์ต USB
ขนาด PSU ที่แนะนำ ปัดขึ้นเป็นหลัก 50 วัตต์:
W_{PSU} = \lceil W_{total} \times 1.3 \div 50 \rceil \times 50
ตัวอย่าง: CPU 65 W + การ์ดจอ 220 W + บอร์ด 50 W + แรม 2 แถว 10 W + SSD 1 ตัว 7 W + ซิงก์ลม 5 W + 15 W = 372 W → แนะนำ PSU 500 W
เกจกำลังไฟในหน้าจัดสเปกแบ่งสีตามเปอร์เซ็นต์การใช้ของ PSU: ต่ำกว่า 70% เขียว · 70–85% เหลือง · เกิน 85% แดง

### 4.4 คะแนนประสิทธิภาพ

แอดมินกรอกคะแนนเปรียบเทียบ 0–100 ให้ CPU และการ์ดจอทุกรุ่นเอง (รุ่นแรงสุดในระบบ = 100) คะแนนรวมของสเปกถ่วงน้ำหนักตามประเภทการใช้งาน:

| ประเภทการใช้งาน | น้ำหนัก CPU | น้ำหนักการ์ดจอ |
|---|---|---|
| เล่นเกม | 0.3 | 0.7 |
| ทำงานออฟฟิศ | 0.8 | 0.2 |
| ตัดต่อ/กราฟิก | 0.5 | 0.5 |
| สตรีม | 0.45 | 0.55 |

Score = w_{CPU} \cdot S_{CPU} + w_{GPU} \cdot S_{GPU}
ความคุ้มค่า = Score ÷ ราคารวม × 10,000 ใช้จัดอันดับและเลือกตัวเลือก "คุ้มสุด"

### 4.5 อัลกอริทึมจัดสเปกตามงบ

สัดส่วนงบเริ่มต้น (แอดมินแก้ได้):

| หมวด | เล่นเกม | ออฟฟิศ | ตัดต่อ | สตรีม |
|---|---|---|---|---|
| CPU | 20% | 30% | 25% | 22% |
| การ์ดจอ | 40% | 0–10% | 30% | 35% |
| เมนบอร์ด | 10% | 15% | 10% | 10% |
| แรม | 7% | 12% | 12% | 9% |
| เก็บข้อมูล | 7% | 15% | 10% | 9% |
| PSU | 7% | 8% | 6% | 7% |
| เคส | 6% | 10% | 5% | 6% |
| ชุดระบายความร้อน | 3% | 0–5% | 2% | 2% |

ขั้นตอน:
- แบ่งงบตามสัดส่วนของประเภทการใช้งานที่เลือก
- เลือกการ์ดจอคะแนนสูงสุดที่ราคาไม่เกินงบหมวด (ข้ามถ้าเป็นออฟฟิศและ CPU มีกราฟิกในตัว)
- เลือก CPU คะแนนสูงสุดภายในงบหมวด
- เลือกเมนบอร์ดที่ผ่าน R01–R02 ราคาถูกสุดที่มีช่อง M.2 อย่างน้อย 1 ช่อง
- เลือกแรมที่ผ่าน R04–R06 ความจุขั้นต่ำ: ออฟฟิศ 16 GB เล่นเกม 16–32 GB ตัดต่อ 32 GB แบบ 2 แถว
- เลือก SSD NVMe ความจุมากสุดในงบหมวด
- คำนวณวัตต์ แล้วเลือก PSU ที่วัตต์ ≥ ค่าแนะนำ ราคาถูกสุด
- เลือกเคสที่ผ่าน R08, R09, R15
- เลือกชุดระบายความร้อนที่ผ่าน R10–R13 ถ้า CPU ไม่มีพัดลมแถม
- รันตรวจทั้งชุด ถ้าเกินงบ ลดรุ่นหมวดที่เกินงบหมวดมากที่สุดทีละขั้นแล้ววนข้อ 10
- ถ้าเหลืองบเกิน 5% อัปเกรดการ์ดจอหรือ CPU ทีละขั้นตามน้ำหนักการใช้งานจนงบหมด
- สร้าง 3 ตัวเลือก: ประหยัด (ใช้ 85% ของงบ) · สมดุล (ใช้ใกล้ 100%) · คุ้มสุด (ความคุ้มค่าสูงสุดในงบ)
ทุกชุดที่ส่งให้ผู้ใช้ต้องไม่มีปัญหาระดับผิดพลาด ถ้าหาไม่ได้ ระบบบอกงบขั้นต่ำที่ทำได้สำหรับประเภทการใช้งานนั้น

### 4.6 ราคาตลาดมือสอง

ราคามือสองทั้งหมดมาจากในระบบเอง ไม่ดึงจากเว็บอื่น ระบบเลือกใช้ 3 แหล่งตามลำดับ และบอกผู้ใช้เสมอว่าราคาที่เห็นมาจากแหล่งไหน

| ลำดับ | แหล่งราคา | ใช้เมื่อ | ป้ายความน่าเชื่อถือ |
|---|---|---|---|
| 1 | รายงานจากสมาชิกที่แอดมินอนุมัติ ช่วง 60 วันล่าสุด | มีอย่างน้อย 3 รายงานในเกรดนั้น | สูง (10 รายงานขึ้นไป) · กลาง (3–9) |
| 2 | ราคากลางที่แอดมินสำรวจตลาดเอง | รายงานไม่ถึง 3 และสำรวจไว้ไม่เกิน 90 วัน | กลาง |
| 3 | สูตรประมาณค่าเสื่อมจากราคาใหม่ | ไม่มีข้อมูลจากสองแหล่งแรก | ประมาณการ |

คำนวณราคากลางจากรายงาน
- เลือกรายงานที่อนุมัติแล้วของรุ่นและเกรดนั้นใน 60 วันล่าสุด
- ตัดค่าผิดปกติด้วยวิธี IQR: ต่ำกว่า Q1 − 1.5 × IQR หรือสูงกว่า Q3 + 1.5 × IQR ทิ้ง
- ให้น้ำหนักรายงานใหม่มากกว่า: อายุ 0–14 วัน × 1.0 · 15–30 วัน × 0.75 · 31–60 วัน × 0.5 และประเภท "ซื้อ/ขายได้จริง" × 1.0 · "เห็นประกาศขาย" × 0.8
- ราคากลาง = มัธยฐานถ่วงน้ำหนัก · ช่วงราคาที่พบบ่อย = เปอร์เซ็นไทล์ที่ 25 ถึง 75
- ปัดเป็นหลัก 50 บาท เก็บผลในตาราง part_used_stats คำนวณใหม่ทุกคืน (Vercel Cron) และทุกครั้งที่อนุมัติรายงาน
สูตรประมาณค่าเสื่อม (ใช้เมื่อไม่มีข้อมูลตลาด)
P_{used} = P_{new} \times r_{cat}^{\,t} \times k_{grade}
t = อายุนับจากปีที่วางขาย (ปี) · k = A 1.00, B 0.90, C 0.75 · r = สัดส่วนราคาที่เหลือต่อปีของแต่ละหมวด:

| หมวด | r ต่อปี |
|---|---|
| CPU | 0.80 |
| การ์ดจอ, แรม | 0.75 |
| เมนบอร์ด, เก็บข้อมูล, เคส, ชุดระบายความร้อน | 0.70 |
| PSU | 0.65 |

ค่าเหล่านี้เป็นค่าตั้งต้นที่ต้องปรับเทียบกับรายงานจริงหลังเปิดใช้ แอดมินแก้ได้ในหน้าตั้งค่า ตัวอย่าง: การ์ดจอราคาใหม่ 12,000 บาท วางขายมา 2 ปี เกรด B → 12,000 × 0.75² × 0.90 = 6,075 → ประมาณ 6,100 บาท
ประเมินราคาที่เจอจริง (M = ราคากลาง)

| ราคาที่ผู้ขายเสนอ | ป้ายที่แสดง |
|---|---|
| ต่ำกว่า 60% ของ M | ⚠️ ถูกผิดปกติ ระวังของเสียหรือมิจฉาชีพ |
| 60–90% ของ M | ✅ ถูก |
| 90–110% ของ M | สมเหตุสมผล |
| มากกว่า 110% ของ M | แพงกว่าตลาด ต่อรองได้ |

กฎเฉพาะมือสอง

| รหัส | ตรวจอะไร | ข้อความ | ระดับ |
|---|---|---|---|
| U01 | การ์ดจอมือสอง | ขอดูรันทดสอบ ถามประวัติการใช้ขุดเหรียญ ดูอุณหภูมิ | เตือน |

## 6. การออกแบบฐานข้อมูล

## 8. สถาปัตยกรรมระบบ

ระบบเป็นโปรเจค Next.js เดียวที่รวมหน้าเว็บและหลังบ้าน Deploy บน Vercel และต่อกับ PostgreSQL บนคลาวด์ จุดเด่นคือ Compatibility Engine เป็นโค้ดกลางที่ทั้งเบราว์เซอร์และเซิร์ฟเวอร์เรียกใช้
สถาปัตยกรรมระบบ · 3 ชั้น + Compatibility Engine ที่ใช้ร่วมกัน
เบราว์เซอร์เรียก Engine เพื่อแสดงผลตรวจทันทีโดยไม่ต้องรอเซิร์ฟเวอร์ ส่วนเซิร์ฟเวอร์เรียกซ้ำตอนบันทึก เพื่อกันคนแก้ผลตรวจจากหน้าเว็บ

### 8.1 ลำดับการทำงานเมื่อผู้ใช้เลือกอะไหล่

- ผู้ใช้กดเลือกอะไหล่ในหน้าต่างเลือก
- Zustand อัปเดตสเปกที่กำลังจัด
- Compatibility Engine คำนวณผลตรวจ วัตต์ ราคา คะแนนในเบราว์เซอร์
- แผงสรุปและรายการปัญหาเปลี่ยนทันที
- ถ้าล็อกอินอยู่ ระบบบันทึกอัตโนมัติหลังหยุดแก้ 2 วินาที ผ่าน Server Action
- Server Action ตรวจสิทธิ์ ตรวจค่าด้วย Zod รัน Engine ซ้ำ แล้วบันทึกลง builds และ build_items

## 9. ความปลอดภัยและข้อกำหนดที่ไม่ใช่ฟังก์ชัน

เว็บต้องปลอดภัยพอใช้งานจริง โหลดเร็วบนมือถือ และใช้งานง่ายสำหรับคนที่ไม่รู้เรื่องคอม เป้าหมายที่วัดได้อยู่ในตาราง 9.2

### 9.1 ความปลอดภัย


| ความเสี่ยง | วิธีป้องกัน |
|---|---|
| รหัสผ่านรั่ว | แฮชรหัสผ่าน (Better Auth จัดการให้) บังคับรหัสอย่างน้อย 8 ตัว ไม่เก็บรหัสผ่านแบบอ่านได้ |
| เดารหัสผ่าน | จำกัดการล็อกอินผิด 5 ครั้งต่อ 15 นาที ต่อ IP และต่อบัญชี |
| ขโมย Session | คุกกี้แบบ HttpOnly, Secure, SameSite=Lax หมดอายุ 7 วัน |
| SQL Injection | ใช้ Drizzle ที่ส่งค่าเป็นพารามิเตอร์เสมอ ไม่ต่อสตริง SQL เอง |
| XSS | React escape ข้อความอัตโนมัติ ห้ามแสดงคอมเมนต์เป็น HTML ตั้ง Content-Security-Policy |
| CSRF | Server Actions ของ Next.js ตรวจ Origin ให้ และคุกกี้ SameSite |
| เข้าหน้าแอดมินโดยไม่มีสิทธิ์ | ตรวจ role ทั้งใน Middleware และในทุก Server Action ฝั่งแอดมิน ไม่เชื่อค่าจากหน้าเว็บ |
| แก้สเปกของคนอื่น | ทุกคำสั่งแก้/ลบตรวจว่า builds.user_id ตรงกับผู้ล็อกอิน |
| สแปมคอมเมนต์/โหวต | จำกัด 10 คอมเมนต์ต่อนาที ต้องยืนยันอีเมลก่อนคอมเมนต์ |
| อัปโหลดไฟล์อันตราย | รับเฉพาะ JPG/PNG/WebP ไม่เกิน 2 MB ตรวจชนิดไฟล์จริง ตั้งชื่อไฟล์ใหม่แบบสุ่ม |
| ข้อมูลส่วนตัว | ไม่แสดงอีเมลบนหน้าสาธารณะ ผู้ใช้ลบบัญชีได้เอง มีหน้านโยบายความเป็นส่วนตัวตาม PDPA |
| ความลับในโค้ด | เก็บรหัสฐานข้อมูลและคีย์ใน Environment Variables ไม่ commit ไฟล์ .env |


### 9.2 ข้อกำหนดที่ไม่ใช่ฟังก์ชัน


| ด้าน | เป้าหมาย | วัดด้วย |
|---|---|---|
| ความเร็วหน้าแรก | LCP ไม่เกิน 2.5 วินาทีบนมือถือ 4G | Lighthouse, Vercel Speed Insights |
| ความเร็วตรวจความเข้ากันได้ | ผลขึ้นภายใน 100 มิลลิวินาทีหลังเลือกอะไหล่ | วัดเวลาในโค้ด |
| คะแนน Lighthouse | Performance, Accessibility, Best Practices, SEO ไม่ต่ำกว่า 90 | Lighthouse |
| รองรับอุปกรณ์ | จอกว้าง 360 px ขึ้นไป Chrome, Safari, Edge, Firefox รุ่นล่าสุด | ทดสอบจริงบนมือถือและ DevTools |
| การเข้าถึง | ใช้คีย์บอร์ดได้ทุกหน้า สีตัวอักษรตัดกันพอ ไม่ใช้สีอย่างเดียวบอกสถานะ (มีไอคอน ❌ ⚠️ ✅ ประกอบ) | axe DevTools |

## 10. แผนการดำเนินงาน การทดสอบ และการนำเสนอ

แผนนี้ใช้เวลา 16 สัปดาห์ ทำส่วนหัวใจ (คลังอะไหล่ จัดสเปก กฎตรวจ) ให้เสร็จก่อนสัปดาห์ที่ 8 เพื่อให้มีของโชว์อาจารย์ได้ตั้งแต่กลางเทอม ถ้าเวลาของเทอมจริงต่างไป ให้ยืดหดตามสัดส่วน

### 10.2 การทดสอบ

- Unit test (Vitest) ทุกกฎ R01–R18 อย่างน้อยกฎละ 2 กรณี (ผ่าน/ไม่ผ่าน) สูตรวัตต์ คะแนน และอัลกอริทึมจัดตามงบ
- Integration test Server Actions สำคัญ: บันทึกสเปก โหวต คอมเมนต์ เพิ่มอะไหล่ ตรวจว่าคนไม่มีสิทธิ์ทำไม่ได้
- E2E test (Playwright) เส้นทางหลัก: สมัคร → จัดสเปกครบ 8 ชิ้น → แก้ปัญหาตามคำแนะนำ → บันทึก → แชร์ → อีกบัญชีเปิดลิงก์แล้วคอมเมนต์
- Black-box test ตารางกรณีทดสอบในรูปเล่ม: ข้อมูลที่ป้อน ผลที่คาด ผลจริง ผ่าน/ไม่ผ่าน
- ทดสอบกับผู้ใช้จริง 30 คน แบ่งเป็นคนที่เคยประกอบคอมและไม่เคย ให้ทำภารกิจจัดสเปกงบ 25,000 บาทสำหรับเล่นเกม
- แบบประเมินความพึงพอใจ มาตรวัด 5 ระดับ ด้านการออกแบบ ด้านการใช้งาน ด้านความถูกต้องของผลตรวจ ด้านประโยชน์ สรุปด้วยค่าเฉลี่ยและส่วนเบี่ยงเบนมาตรฐาน

### 10.3 สคริปต์สาธิตวันสอบ (ประมาณ 7 นาที)

- เปิดหน้าแรกบนจอใหญ่ ให้กรรมการสแกน QR เปิดเว็บบนมือถือตัวเอง
- จัดสเปกสด: เลือก CPU AM5 แล้วจงใจเลือกเมนบอร์ด LGA1700 → ขึ้นแดง R01 กดปุ่มแนะนำเมนบอร์ดที่ใส่ได้ → กลับเป็นเขียว
- เลือกการ์ดจอแรงๆ กับ PSU 450 W → เกจไฟเป็นแดง R14 พร้อมบอกวัตต์ที่ควรใช้
- ใส่งบ 30,000 บาท โหมดเล่นเกม → ได้ 3 ตัวเลือก กดเปิดตัวเลือก "คุ้มสุด" ไปแก้ต่อ
- แชร์สเปก ให้กรรมการกดโหวต/คอมเมนต์จากมือถือ → แจ้งเตือนเด้งบนจอใหญ่แบบสด
- เปิดหลังบ้าน ปรับราคาอะไหล่ 1 ชิ้น → เจ้าของสเปกได้แจ้งเตือนราคาเปลี่ยน → โชว์ Dashboard
- สรุปเทคโนโลยี ผลทดสอบ และผลประเมินความพึงพอใจ
